# Use the assigned Person’s master CV for matching

Accepted during the master CV specification review (S4 and S5).

The app currently reads one workspace résumé from application settings. Editable CRM records need to supply the same résumé to both matching actions so edits affect subsequent runs. A workspace can contain several people with CVs.

Use the assigned Person’s structured master CV for single-job and bulk matching. Suggest the workspace owner by default. Deliver this change with CV import and editing. The new assessment method and PDF workflow can follow independently.

## Assessment ownership

S6 was accepted during specification review. Several people can match the same Source posting. Key the current assessment by Person and Source posting so a second candidate’s run preserves the first candidate’s report. Apply the existing best-source selection separately for each Person.

## Evidence ownership

S7 was accepted during specification review. Employment and independent projects both produce achievements. Keep the achievement with its source and let several CV skills reference it. An edit to the original bullet then appears everywhere that CV cites it.

S8 establishes a shared workspace Skill identity. Evidence links directly to Skill, CV, and Person. The CV’s listed skills remain editable even when the CV supplies no evidence for one of them.

## Legacy job data

S9 assigns every pre-migration Source posting and Job Position to the workspace owner’s Person. This supplies the migration identity for historical reports. New workflow runs retain the Person assignment defined in S5.
